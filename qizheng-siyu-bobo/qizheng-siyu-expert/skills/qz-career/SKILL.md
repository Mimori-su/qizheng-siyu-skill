# qz-career

## Purpose

事业、官禄、工作、名望和升迁专题。2026-10-09 按老师授权原位升级分析程序；案例假说与层级标尺仍待后续检验，客户模板另行确认。中文输出，区分老师已确认规则、程序性整理、模型推理与待验证项。

事业与财运分开：先看本人获得什么职位、职责、专业认可与平台支持，再看事业是否为本人带来收入。完整案例及可识别经历不得写入 Skill 或其示例、镜像。

## When to use this skill

用于职业方向、求职任职、从政、晋升、职场变化、主副业关系及事业方法研究。单纯财运交给 qz-wealth；不因分析职业自动生成婚恋或性格整篇报告。

实际两人合作互补、上下属相处或职场合盘，转到 `../qz-compatibility/SKILL.md`；本 Skill 提供双方各自事业基础，合盘比较另作双向作用。上司用奴仆宫/主，下属用官禄宫/主，不把两个同名或不同地支的人事宫直接重合；单人事业流程及模板状态保持不变。

## Required inputs

已完成的 qz-reader 结构化数据、qz-wangshuai 力量记录、qz-core 原局结论及用户问题；可为本轮内存记录，不要求为满足前置而新建文件。纯方法整理无需另找命盘。真实经历只作反馈；缺失的职业事实、年度资料不补造。

## Output files

需要保存时沿用客户报告与内部理论档的分层归档；用户“不存档”优先。案例研究只交付方法与证据审查，不擅自生成客户报告或保存案例。

## Workflow

1. 继承读盘、力量和原局结论，读取 `resources/career_framework.md`；先拆组织平台、实际任务、个人专长、财源及体感。纯方法整理不补造实盘。
2. 本人四核心与天官、官禄主、官禄宫内星同参，读取 `resources/official_career_rules.md` 和 `../qz-core/resources/tianguan_analysis.md`。多点定位可构成同线，也可形成不同职业线。
3. 每颗参与星及其帮助／制约星复用或补齐 `../qz-wangshuai/SKILL.md` 的逐星全通道与宫度双层记录。先确认作用双方及通道，再读本体、化曜、宿度和神煞；同一星多重身份不重复计力。
4. 分别判断平台支持、实际授权、专业成果、经营能力与自主性；用神力量、本人喜好、兑现阻力和后续补充分别写，不编百分比、官阶或资产换算。
5. 时间问题读取 `../qz-core/resources/original_vs_transit.md`，依既定限运次序核对。已发生、计划中、时间不明分别处理；局部复盘不冒称完整应期验证。
6. 官非、合同争议、组织责任纳入本专题，读取 `../qz-core/resources/dispute_risk_rules.md`，财务纠纷同时接 qz-wealth；不调用独立官非 Skill。
7. 报告或方法总结读取 `resources/career_report_rules.md`；单项客户正文也先读 `../qz-report/resources/report_style.md`。报告结论先行；研究只抽象方法、支持／反证与待验假说。未经确认不把新客户模板设为默认。

## Rules

- Reader 只读盘，不解读。
- Core 只基于 qz-reader 结构化数据分析；`qz_structured_data.md` 为保存时的文件形式，不绕开数据契约。
- 专题必须继承 Core 结论；`qz_core_report.md` 为保存时的文件形式，不能为专题另改原局喜忌。
- 命主旺弱不直接等于事业层次；天官有力、官杀混杂、太阳交感等均不能单条件决定职业类型或结果。
- 不把雇主行业当本人专业，不把资源经手权当决策权，不把贵人财富当本人财富。
- 化曜同名不同体系保留原字段及起法；不能把原盘所有“天印”统一改作正官。
- 不使用确定性、恐吓式、绝对化语言。
- 引用教材时给出章节或页码范围；教材未明确时直接说明。

## Safety rules

- 疾病问题：只作传统术数取象参考，提醒咨询医生。
- 法律问题：只作传统术数取象参考，提醒咨询律师。
- 投资问题：不提供投资建议或收益预测，提醒咨询持牌专业人士。
- 心理危机或现实危险：建议寻求现实专业帮助或紧急服务。
