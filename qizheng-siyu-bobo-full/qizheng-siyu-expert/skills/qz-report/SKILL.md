# qz-report

## Purpose

报告整合器。本 Skill 输出以中文为主，所有结论都要区分“已确认规则”“整理后的分析框架”“模型推理”“不确定项”。

## When to use this skill

当用户请求与本 Skill 定位一致的学习、读盘、核心分析、专题分析、校时或报告整合任务时使用。若用户请求超出本 Skill 边界，先说明边界并交给对应上游或下游 Skill。

## Required inputs

实际报告需读盘、旺衰、原局及相关专题记录，可以是本轮对话结果或已有文件。限运另需对应日期与引动资料，缺项仅限制对应部分。只问使用说明无需命盘，不强制建立内部报告文件。

## Output files

跨专题整合为 qz_full_report.md。限运专题使用独立的 qz_tianshu_timing_internal.md 与 qz_tianshu_timing_report.md；用户要求“不存档”时仅在对话交付，不创建报告或案例文件。

## Workflow

1. 先分请求：问候／使用指南按 `resources/usage_guide.md`；有完整盘面但未指定问题，按 `resources/quick_overview_template.md`；有明确单项则仅处理该项；综合报告按明确范围整合。使用指南不进入读盘前置。
2. 生成任何客户正文前先读 `resources/report_style.md` 的“语言的艺术”规则，包含“分析式表达：有理有据、有重点、有结构”，再按需读取专题模板。主要判断在客户正文中保留关键依据、作用推导与具体人事，交付前按该节检查；单项同样执行，不必把单项扩大为全科。
3. 实际分析核对上游记录；按数据契约和专题框架完成证据，再组织对应篇幅。简析只压缩输出，不跳过原局或专题必要分析。
4. 内部保留支持因素、制约因素、缺失数据和不确定项；客户正文围绕实际问题直接分析，充分说明成立的助力，执行“避免防御性写作”。影响结论的条件与原因融入对应判断；不预设读者误解，不为正反平衡强加负面，删除无信息增量的免责和退让句。
5. 严格遵守本 Skill 的职责边界。

## 通用证据与交付

- Reader 只读盘，不解读。
- Core 基于 `qz_structured_data.md` 或对话中经复核的等价结构化结果分析，不绕开数据契约。
- 专题 Skill 必须继承 `qz_core_report.md` 或对话中经复核的等价原局结果，不能各自独立乱断；不为满足文件名而强制存档。
- 只有出生年月日时而没有实际排盘时，交 qz-reader 说明数据需求，不能为了凑齐简析推造星位。归档沿用既有授权；“不存档”优先于所有保存措辞。
- `scripts/assemble_report.py` 是旧版内部文本拼接工具，会原样带出 core；不得用于生成客户版、单项或简析，也不得把其输出直接当作已完成的报告整合。新的报告按本文件及模板直接组织。

## 专题报告路由

### 首次总览

- 「命盘简析｜首次总览」采用六节，约800–1200字；末尾三个针对本盘的可复制追问。使用指南、简析和语言层均为本模块内置资源，不新增 Skill；不覆盖详细性格、婚恋、格局等已确认模板。

### 学业、学历、升学与资格证

- 继承 qz-career 的 `../qz-career/resources/education_framework.md`，沿“核心结论 → 具体分析 → 针对性建议”组织，择要回答求学／学历支持、学习性质与地域、阻力及所问行运。区分学习能力、学历凭证、考试或资格认证与实际任职，不用其中一项替代其余。个人求学问题不交 qz-study；qz-study 用于知识学习整理。只问单项时收窄范围，不扩写未问的事业或全科报告。

### 出身与父母

- 出身与父母专题继承 `../qz-core/resources/parents_framework.md`，读取 `resources/parents_report_template.md`：客户按总评、父亲、母亲、家庭资源、阶段建议五部分择要，内部单列人物定位、宫宿通道、力量、传递链与行运年龄证据。父母自身条件、家产、实际给到命主的支持和体感分开；不把年干偏财或田宅宫内星机械当父亲，不把关系变化固定在童年。方法教学不生成个人档案，完整案例不得进入 Skill。

### 事业与财运

- 财运专题读取 `../qz-wealth/resources/wealth_report_rules.md` 的七板块：财富总评、财富形态与实际支配、家底与承接、自己的求财本领与路数、留存分配传承、重要阶段变化、发挥优势建议。继承 qz-wealth 原局与财源规则；出身、自主求财、阶段所得、积累传承四轴带主体与时段，不把企业／家庭规模、股票持仓、分红和个人现金混同。取得、承受、支配、转换与损耗分别表达，不用命主旺弱抹去已成立财源，未决的继承和股权细分判法不补造。客户／内部独立，单项按范围压缩，其他专题模板不变。己化月勘误沿 qz-wealth 表，不自行重建财星身份。
- 财富总评按 `../qz-wealth/resources/wealth_framework.md` 第10节继承经验量级及助力：多路旺财、生财、承载合看；日月会财、日月联系命身，以及岁殿岁驾、禄马官魁文、三元禄有效会财均作正向依据。命身贵助不只写体感；只问量级先给经验潜力档和二至四条关键依据，不扩写行业，也不把档位当已核实资产。
- 官非只在事业／财运有关内容中呈现，共用 `../qz-core/resources/dispute_risk_rules.md`；同一纠纷跨专题合并，不另设官非 Skill 或固定重复章节。

### 婚恋

- 完整婚恋客户报告优先保留 qz-love 的八板块格式（见 `../qz-love/resources/client_report_template.md`）：仅婚恋专题可直接交付其客户版；多专题整合时保留婚恋章的八个小节。下方通用技术标题不得覆盖婚恋客户版，也不得把内部审查内容混入客户正文。

### 本命格局

- 单独交付本命格局客户报告时，先完成含“候选用神 → 原局可用性复核 → 叠象成就方向”的内部理论档，再按下方 Vault 模板「文件二」生成客户版：一句总评、几条“简明格局依据＋现实意义”，随后以人生主轴、立身本领、事业形态、财富结构、社会成就、外部资源、发展空间与限制、成就所需投入与生活质量为覆盖清单。相近内容合并，不跨节重复；具体写行业、角色、资源和发挥路径，不能把多重取象压成单星旺衰或心理描述。若 qz-core 已核定传统格局名，客户版通常只选一至两个正向雅称，并在同句或下一句解释现实意义；不展示负向格名、不堆叠名目，也不以格名承诺结果，真实制约仍须温和如实说明。结尾给有依据的鼓励与一句参考说明；证据充分时直接表达适合方向，关键不确定与真实制约仍保留。不改变性格、婚恋及通用跨专题报告的顺序。

### 限运与天官

- 限运客户报告读取 `resources/timing_report_template.md`，先形成内部理论档，再输出“核心判断 → 阶段变化 → 重点事件 → 关键年份 → 行动建议与鼓励”五板块。完整宫限、单年、单专题分配不同篇幅；按实际日期而非固定十年。阶段讲重心、事件讲得失、年份讲触发，同一事件多次引动合并表达，内部保留全部路径，不计分也不增设顶星应事门槛。所有参与星的躔度、神煞须落实到有据的叠象描述。单专题继承其规则，完整婚恋八板块不被替换。
- 天官结论继承 qz-core 和限运内部档（规则见 `../qz-core/resources/tianguan_analysis.md`），不得在整合时补造。本命融入事业形态、社会成就、外部资源；限运融入重点事件与关键年份，不新增重复长章。内部保留本体作用与化曜关系两层及身份口径，客户具体说明已成立的帮助及其发挥路径，影响判断的限制或成本随对应原因说明；有化曜事件象不等于原局可用或保证成功，原局受制也不抹去该象。天官推演不只是雅称，不与仅供命名的格局名混同。

### 健康与校时

- 健康按 qz-health 同时检查身体、心理及其联系；单问健康也应用本模块文风，医学与现实安全边界不因要求自信而取消。
- 生时校正按 qz-rectifier 候选盘／事件对比模板，只陈列支持、冲突和缺项，不用匹配分或百分比代替分析。

## 统一表达与依据

- 表达直接、自信，结论强度与证据相称；不恐吓、不作无依据的绝对断言，不靠逐段免责体现严谨。
- 区分已确认规则、整理框架、推演与待核项；未明确的判法直接说明。

## Safety rules

- 疾病问题：只作传统术数取象参考，提醒咨询医生。
- 法律问题：只作传统术数取象参考，提醒咨询律师。
- 投资问题：不提供投资建议或收益预测，提醒咨询持牌专业人士。
- 心理危机或现实危险：建议寻求现实专业帮助或紧急服务。

## 通用 Output format

以下仅供内部证据记录，不当作客户正文。客户单项优先专题模板；没有专门模板的单项，用“核心结论 → 具体分析 → 针对性建议”短结构。婚恋、本命格局、限运各自模板不变，简析按 quick_overview_template.md。

```markdown
## 问题

## 数据基础

## 支持因素

## 制约因素

## 规则依据与待核项

## 谨慎结论

## 需要继续确认
```
