# 顶星计算：采用既定顶星方法

采用已确认的顶星数值判据，方法标识为 `palace-degree-29-1-v1`。本入口负责计算命中，Core 负责解释；其他断语、案例反馈及引擎行为均须独立核验，不随公式自动采用。

## 采用的判据

公式只用于计算命中；月限生克与调候属于不同分析层，不混作顶星判据。

1. 中心是**本盘所问时刻的真实行度黄经**，不是出生的命度、年初限度或所选某颗星；本命与流曜都与这一个中心比较。
2. `中心宫内度 = normalize(中心黄经) % 30`；`星宫内度 = normalize(星黄经) % 30`，黄经先归一到 `[0,360)`。两星不必同一地支宫。这是30度宫内位置比较，**不是二十八宿宿内度，也不是两黄经的最短角距**。
3. 半宽 `W = (30 / 限年数) / 2`。限年数必须来自本盘适用于本次计算的限段依据，不能拿年龄、当前宿剩余年数或任意固定值充当。
4. 常规命中为 `abs(星宫内度 - 中心宫内度) <= W`，边界包含等号。脚本按输入数值可表示的十进制值作有理数计算、输出时才转为JSON数值，避免10.1与41.1的浮点取模误差造成端点漏判；不额外扩大W或29/1边界。
5. 另有29/1特例：一方宫内度 `>=29`，另一方 `<1`，即命中，**不另要求差值落入W**。29包含、1不包含；这不是将常规距离折算成环形距离。输出标清 `boundary_29_1`；只靠此条命中时再标 `boundary_only=true`，与不采用此条的软件盘面可有差异。
6. 只扫描日、月、金、木、水、火、土、计、罗、炁、孛；本命与流曜分栏，不加入外部引擎扫描的天王、海王、冥王或斗、罡。

外部引擎的具体取数口径：`Main.java` 将指定流年盘日期的当地 **12:00** 传给 `getLimitPosition`，默认为01-01；它另打印的“年初限度”不能替代该中心。其 `getLimitHalfWidth(age)` 以虚岁 `age−1` 从限段序列递减选段，段首为童限天数÷365.25，其余为 `limit_seq`，严格 `< 段年数`，等于边界时移入下一段。**本脚本不重造该选段算法、不插值行度**：要求上游给真实中心和有来源的限年数；若使用其他已核实取数方式，记录其具体方法。虚岁选段与实际日期行度可能不在同一边界口径，遇交限须核限年数来源，不能凭宫名猜年数。

## 输入与调用

用纯 Python 标准库运行 `../scripts/calculate_topstars.py`，从标准输入接收一个 JSON 对象，标准输出返回 JSON。可在内存导入 `calculate_topstars(data)`；脚本不写命盘文件，不需要 Java 或星历库。

下面仅为匿名数值示例，**不能作真实客户起盘数据**：

```json
{
  "chart_version": "anonymous-fixture-v1",
  "at": "2026-12-20T12:00:00+08:00",
  "coordinate_system": "郑氏星案恒星制",
  "coordinate_profile": "同一黄经零点、岁差与宿界口径的明确说明",
  "center": {
    "longitude_deg": 240.998,
    "at": "2026-12-20T12:00:00+08:00",
    "source": "本盘行度来源、算法版本和取数位置"
  },
  "limit": {"years": 10, "source": "本盘限年数及选段方法"},
  "natal": {
    "source": "同一出生资料版本的原盘黄经来源",
    "stars": [{"name": "木", "longitude_deg": 1.618}, {"name": "炁", "longitude_deg": 179.766}]
  },
  "transit": {
    "at": "2026-12-20T12:00:00+08:00",
    "source": "本次时刻流曜来源与版本",
    "stars": [{"name": "日", "longitude_deg": 270.5}]
  }
}
```

`chart_version` 绑定同一出生资料版本，`coordinate_profile` 声明中心、本命黄经、流曜黄经共用的坐标口径；上游须实际核实，脚本不能仅凭文字确认两个引擎兼容。不得混入另一盘的中心、限年数或星位。`source` 可补充原始字段、版本、精度与参数，整个输入会在输出 `input` 中原样保留。未获用户存档要求时只在内存／标准流传递。

`at`、`center.at`、`transit.at` 使用含时区偏移的完整 ISO 时刻；后两者必须与 `at` 代表同一瞬间，允许等价的不同时区表达。只有年份、没有中心或缺限年数来源时先补对应数据，不默认到年初，不编造中心。缺本命／流曜某一组时可省略该组，已有组照算；不将缺组当成无星。

每组可提供部分十一曜，输出 `partial` 与 `missing_stars`；十一曜齐全才为 `complete`。省略组是 `not_provided`。组内星名不重复，星名统一用单字（炁可在上游从“气／紫气”有来源地规范化），`流木` 不作独立星名。未知星名会被拒绝，调用者先按白名单选择，不能让星官或新行星参与。半宽和黄经须为有限数值，限年数须大于0。错误时返回退出码2，标准输出为空。

## 输出与解释

输出含 `meta.method`、`scope=instant_candidates`、原始 `input`、`half_width_deg`、`center_palace_degree`，以及本命／流曜各自的 `checked`、`hits`、`missing_stars`。每颗核查星保留归一黄经、宫内度、有符号差值、命中路径和是否仅靠29/1特例。

“候选”指**某时点的计算命中**；方法已采用，实际缺项按数据缺口处理，事件解释交给 Core。继续遵守既有“顶星会发生相关事情”的取象，不增设必须凑齐其他信号才算的门槛；具体是什么事、吉凶及现实日期仍由完整分析和反馈区分，不能把命中日写成具体事件必发日。

逐日检查可用于寻找样本命中窗口：查询月内各时刻时，须同步取每个时点的真实行度和流曜；不能只查月初／月中就断全月无顶星。每日固定时刻采样也可能漏掉快行星窗口，未作连续边界求解只能称“已查询时点命中”；本工具不输出窗口起止、不证明整月空顶、不默认扫描区间。不能断言“每月必然扫过一次”或“窗口日等于应事日”。

数值校对： `240.998 % 30 = 0.998`，配 `179.766 % 30 = 29.766` 经29/1命中；若将 `238.182 % 30` 写为1.182则是错误，正确为28.182，不满足29/1；本入口按原始黄经实算。
