# 输入出生时间起盘

适用于依据出生资料生成七政四余本命盘，或为校时生成候选盘。依次核实输入、时间换算、引擎能力与盘面交付；采用既定恒星制，不在此另定立命／起限算法。

## 1. 收集可以重现的输入

用户可按日常方式提供出生年月日、钟表时间和出生地。先提取已有资料，只补问影响计算的缺项，不让用户填写与所问无关的信息。

| 字段 | 规则 |
|---|---|
| 日期与历法 | 明确公历或农历。农历须有闰月标记，并经可核查历法转换后才送入公历引擎；保留原输入及转换来源。 |
| 时间与精度 | 保留原始时分秒、是否约数及可信范围。只有时辰或一个区间时生成候选盘；不把时辰中点冒充精确出生时间。 |
| 时间基准 | 明确是出生地钟表时间、地方平太阳时、已校正真太阳时，还是某软件要求的兼容输入。未说明时先确认，不静默假定已校正。 |
| 出生地 | 城市及地区足够定位时，核实经纬度来源；重名地点或精度影响边界时再补问。经度东正西负，纬度北正南负；调用前核参数先纬后经还是先经后纬。 |
| 时区 | 按出生地与出生年月日核历史时区和夏令时；落入当地夏令时区间须先提醒确认时间口径，依第1.1节处理。当前聊天时区不能代替出生地时区。 |
| 性别 | 可收集；不因未给性别阻断男女均以命度主为中心的共同原局流程。只在具体算法或专题确需时补问。 |
| 目标时点 | 需要年运、流曜才另记目标年份／日期时间；与出生时点分开。不沿用引擎硬编码默认年份。 |

“现在起盘”须依上下文区分本命排盘、择时或指定时点流曜。未给出生日期时，不把当前日期当出生日期。

### 1.1 夏令时核验与确认

**出生时间落在出生地当年的夏令时有效区间，先提醒对方确认时间口径，再定时辰。整个有效区间都触发，不只在拨表当天。** 已在本轮明确确认的同一时间／地点／校正方法可复用答复，不反复问；资料变化后重新核验。

1. 先辨输入是当时钟表时间、已扣夏令时的标准时间、地方平太阳时还是真太阳时。未说明时可将原值作为“当地钟表时间假设”检测，结果不能当作已确认出生时点。明确已校正的时间不可再次当民用钟表时间查表；先核原始值及校正方法。
2. 用出生地对应的历史 IANA 时区核具体日期与时间，不能仅凭国家、月份、现行时区或当前是否实行夏令时判断。调用 `scripts/check_birth_time.py`，按返回状态处理。时区资料缺失、地点不明或来源冲突时记“历史时制待核”，不能判“无夏令时”。
3. `confirmation_required=true` 时，先在对话中询问并等待与该时间有关的答复。只整理其余资料；确认前不选定正式出生时辰或本命盘。若对方不能确认，保留可解释的候选和原因，需要时进入候选盘比较，不替对方挑一个时间。
4. 提醒句可用：“你出生地在这个日期实行夏令时。请确认所填时间是①当时钟表显示的时间（含夏令时），②已经扣除夏令时的标准时间，③已经换算的平太阳时／真太阳时，还是④暂不确定？这会影响时辰，确认后再起盘。”实际资料仅能证明季节性时制调整时，采用工具的相应表述，不强称特定法律名称。
5. 若为当时含夏令时的钟表时间，采用核实的实际 UTC 偏移转换一次；不能先手减一小时、再交给会自动处理夏令时的时区工具。若已扣除或已转太阳时，核所用基准、经度及均时差处理，避免重复扣除。夏令时调整未必为一小时，不硬编码 `-1h`。
6. 回拨产生重复钟表时间时，保留两个 UTC 候选，确认拨表前／后；拨快产生不存在时间时，提示核原始记录，不擅自平移到下一有效时刻。即使其中一个候选不在夏令时，也必须确认。时间区间跨过换表点时分别核候选，不取中点规避问题。
7. 确认后保存原值、对方确认内容、时区来源、实际偏移、转换后时刻和是否跨时辰；“不存档”时记录只在本轮对话／内存中保留。

工具使用Python标准库 `zoneinfo`，需要本机有相应IANA时区数据；只读标准输入JSON并输出JSON，不改写输入或保存客户文件。从 qz-reader 目录调用：

```bash
python -B scripts/check_birth_time.py
```

标准输入字段：`local_time`（无偏移的公历日期与时分，可含秒）、`timezone`（例如 `Asia/Shanghai`）、`time_basis`（`unknown`／`civil`／`standard`／`mean_solar`／`apparent_solar`）。模型在内存组织字段，用户不必填写JSON。

返回 `unique`、`ambiguous`、`nonexistent`、`timezone_unknown` 或 `basis_requires_review`；同时给出夏令时状态、实际偏移、有效UTC候选和提醒语。已校正时间不会被工具伪装成民用时间生成UTC。命令成功仅表示检查完成；必须看状态及待确认项。`unknown` 基准下的候选是条件结果，不能仅因有一个候选就视为确认。

## 2. 时间只按声明的接口换算

同时保留三类字段：**用户原始时间**、**可确定的真实时点（含 UTC）**、**送入排盘引擎的参数**。即使显示字符串相同，也不合并其含义。

- 出生地当时的民用钟表时间（含当地当时实际夏令时）按历史时区确定 UTC；已经扣过夏令时的标准时间须按确认过的标准偏移还原，不能再次按含夏令时的民用时区解释。若引擎接口要求地方太阳时，再按已核定的经度改正与均时差方法换算一次，记录方法、符号、日期跨越及精度。
- 用户明确给的是已校正真太阳时，不再次加经度差或均时差。若还要计算流曜、节气或需要真实 UTC，而原始钟表时间缺失，须用经验证的方法反解或补问；不能把真太阳时字符串直接贴上 `+08:00` 当真实时点。
- 真太阳时换算、子初换日规则、时辰分段、立春换年和节气换月是不同步骤，分别记录；不得以“统一口径”为名改写原始出生日期。
- 引擎只接受分钟时，须保留输入秒数及截断／舍入策略；临界出生或校时不得默默丢弃秒数，也不得把分钟吸附到下一时辰。若工具无法支持所需精度，只限制相关比较。
- 本包 `calculate_transits.py` 与 `calculate_periods.py` 接受带时区的真实时间；它们不接受未经反解的太阳时或 App 兼容时间。新本命引擎不能改变这两个入口的时间含义。

## 3. 选择引擎与校验口径

仅使用在当前环境中实际运行成功、输出足够且计算口径已核对的本命引擎。`calculate_transits.py` 只算指定时点流曜，不能替代立命、命身宫度或洞微起限。引擎文件存在、命令退出成功和某一锚点吻合都不等于完整验收。

每次起盘保留：引擎版本／摘要、输入回显、历法／时区／时间基准、黄道或赤道、回归或恒星、岁差参数、宫界、宿界、计罗定义、月孛口径、换日规则、星历覆盖和实际查询时点。不得仅凭引擎名称或“恒星”标签认定与现行工具一致。

接入新引擎时核查：

1. 命宫、命度、命度主、身宫、身度、身度主及十一曜落宫／宿度齐全；十二人事宫映射唯一完整，缺字段不能由模板补齐。
2. 同一颗星的原始黄经、宫位、宿名及宿内度使用可解释的一致坐标。命度／限度若另用坐标，逐项标注转换，不与恒星星位直接相减。
3. 用已核实的同参数盘面比较，并检查时辰、换日、宫界／宿界附近的候选时刻；避免只拟合一个锚盘。细微时间变化造成不明跳变时，保留差异，不自动选“更像”的结果。
4. 现有原盘、引擎新盘分别保存来源。不同引擎的命宫、宿度、四余、限表不能挑字段拼成一张“完整盘”；先解决口径差异。
5. 起限、小限、飞限、顶星及流曜分别验收。本命盘通过不代表该引擎的所有附带功能都通过；小限／飞限／月限继续按本包现行规则计算。

## 4. 候选本命引擎的接入条件

经源码与本机运行检查，候选跨机本命引擎**仍待适配、校准，不作默认本命排盘来源**。候选本命引擎未随本 Skill 提供；本包也不嵌入 Windows runtime 或完整案例库。接入须解决：

- 候选引擎原运行环境为 Windows x64 Java 21；原 JAR 的 class major 为 65。已检查的 macOS Java 17 无法运行该 JAR，未验证跨平台起盘成功。
- 文档要求真太阳时直输，但代码仍经指定时区转换，并对立命使用 `snapToSignStart` 的时辰吸附逻辑；该逻辑自注为锚点吻合工作假设。必须先校正接口含义及边界，不能称为一般真太阳时天文反解。
- 默认 CLI 输出日月位置，`-full` 增加神煞，并不提供完整十一曜本命表与十二宫映射；底层接口存在不等于 CLI 已能完整交付。
- 换限名称串为“命相福官迁疾妻奴男女田兄财”，却以单字符索引十二段，存在把“男女”拆开、财帛遗漏的标签问题；该表不能直接喂给现行飞限计算器。
- ZZT 宿界、岁差作用空间、小限年界仍按各自参数核对。顶星采用已确认的顶星公式与跨界特例，独立入口见 `topstar_query.md`；这不等于Java原始输出的全部时点和字段已可直接使用，年初限度也不能代替指定时刻行度。
- 代码具有缺星历后尝试下载的路径。离线适配应明确缺资源失败；常规起盘不应隐式下载或写入未知资源。README 的失败说明不替代代码行为验证。

后续最低接入条件：可运行的当前平台构建、完整原始盘面导出、时间和宫名问题修复、同口径锚盘及边界验证、缺星历行为明确。通过前可以整理输入、解释差异及读取用户已有盘面，不能生成假定星位或宣称已完成起盘。

## 5. Reader 交付

实际得到合格盘面后，按 `data_contract.md` 填写十节记录；保留原始输出及逐字段来源、缺项和差异。只有必要命身字段与十一曜位置满足 `validation_rules.md`，才进入旺衰和 Core。宫限、度限日期或精确顶星未通过校验时，限制相应应期层，不把它们当已知。

无可用引擎时，明确说明“已整理出生参数，但尚未取得可靠的完整本命盘”，列明具体工具缺口，允许用户提供现有盘面继续。用户“不存档”时输入、换算、结构化结果均在内存／对话中传递，不新建出生资料或案例文件。

推荐用户输入示例（仅格式，不是真实案例）：

> 公历 YYYY-MM-DD，出生地钟表时间 HH:mm（是否约数），出生地：国家／省市。请按既定恒星制起本命盘；如需要太阳时换算，请保留原时间并说明所用方法。本次不存档。
