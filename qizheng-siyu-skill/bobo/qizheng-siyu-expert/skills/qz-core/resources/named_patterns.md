# 传统格局名候选索引与调用规范

## 一、资源定位

本资源供 qz-core 在**原局喜忌、力量、有效交感、候选用神可用性、命主承接和现实方向均已分析完成后**调用。传统格局名称只承担：

1. 给内部已识别的作用结构建立检索名称；
2. 为客户报告中已经成立的正向结构增加简洁、雅致的表达。

候选名录保存在同目录 `named_pattern_catalog.md`，只在需要核对具体格名与条件分支时按需读取。该资料目前是**格名与条件分支索引**，不是一张可直接触发结论的规则表。已确认规则、现行四时条件分支、十一曜实际力量和 qz-core 的原局可用性结论优先。

不得用格名重新裁决喜忌，不得从好听的名称反向挑选证据，也不得把软件列出的候选格局当作已经成立。

## 二、固定核验流程

```text
完成原局结论
  → 匹配候选形态
  → 确认候选条目及同名分支
  → 核原局／行限适用范围
  → 核季节、昼夜、月相
  → 核宫位、宿度、前后次序及距离
  → 核命度主关系、主用身份与有效交感
  → 比较相关星曜实际力量
  → 核受伤、救应、命主承接和破格条件
  → 判成立状态
  → 翻译现实含义
  → 决定是否展示名称
```

任何一步缺少关键条件，均不得按“成立”处理。单星入垣、升殿、同宫、对照、某宿或一项神煞，通常只形成候选形态，不足以单独定格。

同一结构的多个别名只算一个证据。相同名称若对应不同结构、不同条件或相反吉凶，必须按条件分支拆开记录，不能合并成一个宽泛触发器。

## 四、成立状态与客户展示

### 1. 成立

条件完整、作用关系与实际力量支持、无关键破格，且命主能够承接。客户版可点名正向雅称，但必须立刻解释它在本盘代表的能力、资源、发展方式及主要条件。

### 2. 有形但受限

主要形态存在，但力量、交感、受伤、救应或承接有限。客户版如确有表达价值，可写：

> 有“……”之象，优势在于……；但……会限制它的发挥。

不得省略“但”之后的真实制约。

### 3. 仅见单项条件

通常只留内部，不向客户展示名称。需要说明时，只写“见到相关结构线索”，不得称为成格。

### 4. 不成立／待确认

不进入客户正文；内部保留不成立原因或缺失条件，供后续核查。

## 五、客户版边界

- 每篇报告通常只选一至两个最贴切、证据最完整的正向格名；没有干净成立的名称就不用。
- 格名必须服务于结论，不能连续罗列、不能代替白话分析、不能把别名当成多重加分。
- 负向格名、贱格名，以及带贫困、刑伤、疾病、婚变、寿命或人格贬损意味的名称，只留内部复核。客户版不贴标签，但对应的现实压力、代价、成立条件和改善方向仍须如实、温和地表达。
- “大贵、巨富、极品、必……”等旧式评价只保留为待核条文，不据此承诺财富、职位、阶层、婚姻、健康或寿命结果。
- 正向表达不等于把坏的说成好的。格局被制、力量不足、作用对象不对或命主承接有限时，必须同段交代。

## 六、推荐表达

> 这一处有“金白水清”之意：思路、判断与表达较容易形成配合；但是否能稳定转成成果，仍取决于金水在原局是否都能发挥并真正作用到命主。

> 可借“向阳花木”形容这份结构：合适的平台或师友更容易让个人长处被看见。若木盛而遮光，则帮助与竞争空间也可能同时存在。

> 盘中见“子母重逢”的结构线索，说明资源与命主有相接的可能；恩星的力量、有效交感与命主承接，决定它是稳定助力还是阶段性机会。

避免：

> 你就是某某格，必定富贵。

## 七、已知冲突与待核项

下列项目不能自动调用，必须回查条件分支：

- **日月合璧**：资料中既指日月同宫／对照／三合，也指相邻日月宿各自升殿；
- **水火既济**：既有子午分居的定义，也有同宫并论前后次序的定义；
- **金骑人马、太乙抱蟾**：同名兼有正向与负向分支；
- **日月失垣／失殿**：未得加分不自动等于受损；
- **火月交辉、祥云捧月**：须补核月相、昼夜、寒暖及争光／遮蔽条件；
- **补遗中的行限条目**：不得移作本命原局规则；
- 同名异义或相反断语未完成校勘时，成立状态一律记为“待确认”。

## 八、调用优先级

- 候选索引：`named_pattern_catalog.md`；
- 第一优先：已确认的条件化规则；
- 第二优先：现行四时喜忌条件分支、qz-wangshuai 十一曜力量基线、qz-core 原局可用性结论；
- 第三优先：本候选格名索引，仅用于核名与表达；
- 发生冲突时，并列条件分支并标待核，不静默覆盖现行规则。
