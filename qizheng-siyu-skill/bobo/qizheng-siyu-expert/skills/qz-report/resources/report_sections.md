# 完整报告章节

`qz-report` 只整合既有报告，不新增断语。

专题若有专用客户版结构，应优先保留。完整婚恋报告沿用 qz-love 八板块；本命格局客户版按 Vault「本命格局报告模板」结论先行、八方面展开、证据支持的鼓励收束。限运报告按 `timing_report_template.md` 的五板块：核心判断、阶段变化、重点事件、关键年份、行动建议与鼓励；按完整宫限／单年／单专题调整详略，客户版和内部档分开。以下通用顺序只用于内部汇总或跨专题外层，不能把技术审查标题塞进专题客户正文。

## 内部汇总顺序

1. 报告声明：传统术数取象参考，非医学/法律/财务/心理专业意见。
2. 数据基础：列出 `qz_structured_data.md`、`qz_core_report.md` 和专题报告来源。
3. 数据完整性：合并各报告的缺失字段和低可信度项。
4. Core 摘要：太极、命身、原局结构、喜忌、可继承结论。
5. 专题章节：感情、财运、健康、事业、学业学历、子女、择日、校时等；官非放入相关事业／财运章节，不另立专题 Skill。
6. 正反双审：总支持因素、总制约因素和不确定项。
7. 后续确认清单：需要补充的盘面、事件、现实专业意见。

## 合并原则

同一结论重复出现时保留最完整证据；结论冲突时不强行调和，列为不确定项。

客户单项同样先读 `report_style.md`，没有专门章法时按“核心结论 → 具体分析 → 针对性建议”，不按上述内部次序交付。学业、学历、升学与资格证继承 `../../qz-career/resources/education_framework.md`，在此短结构中择要回答求学／学历支持、性质与地域、阻力、行运，不另扩成全科报告。首次简析使用 `quick_overview_template.md`，使用说明使用 `usage_guide.md`，均不新增推断规则。
