# 校验规则

本规则用于 `validate_structured_data.py` 和人工复核，目标是让 Core 只继承可追溯的数据。

## 必须存在的章节

- 元信息、数据完整性、太极与命身、七政四余星曜位置。
- 十二宫、二十八宿、神煞、原局初步标记、运势资料、校验结果。

## 字段完整性

- 命宫、命度、命度主、身宫、身度、身度主逐项检查实际值；空白、未知、待补、待确认不算有效值。
- 七政四余不只检查 11 个行名，还要检查各星实际落宫与宿度；表头齐全、空模板不能判可分析。
- 每张表都应保留来源和可信度；没有来源时不得标高可信度。
- 性别缺失记未知；男女均以命度主为中心，不阻断共同原局、旺衰、格局分析。只有专题确实依赖该信息时才局部补问。

## 一致性检查

- 出生资料起盘另核 `natal_chart_input.md`：原始时间、真实时点、引擎参数可追溯；时区／太阳时无重复换算，宫宿及限度坐标不混用。引擎输出缺十一曜或宫名错位时不能以“退出成功”判定可分析。
- 命中夏令时有效区间、换表歧义或历史时制待核时，须有相应时间口径确认；未确认不选定出生时辰。核已扣夏令时／已转太阳时是否重复修正，不把 `check_birth_time.py` 的条件UTC候选当作用户已确认的出生时点。
- 顶星核算法与参数来源，中心使用查询时刻真实行度；本命／流曜分栏，流曜与中心时点一致。既定顶星方法已获用户采用，缺失的是具体数据时不得误报为算法未获确认。
- 命度、身度、星宿/度是否与二十八宿表一致。
- 十二宫内星曜是否能在星曜位置表中找到。
- 神煞是否标明位置和作用领域，不能只列名称。
- 流年、限度、倒限要与原局字段分开，避免混读。
- 原始相位（含刑、对刑）及逐星身份保留完整；没提供与明确无项分开。不得让通用交感筛选损失健康专题需要的原始输入。

## 进入 Core 的条件

关键命身字段缺失时，只能生成补数清单；字段有低可信度时，Core 只能做初步框架并标注不确定项。

脚本校验只是基础数据检查，不等于完整数据契约、术数逻辑或客户结论已经通过。契约附表仍须人工复核；缺专题必要数据时限制该专题，不用“格式通过”宣称资料完整。
