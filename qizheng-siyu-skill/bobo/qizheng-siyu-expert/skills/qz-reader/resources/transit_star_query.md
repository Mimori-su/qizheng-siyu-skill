# 指定时刻的恒星制流曜查询

用途：查看被引动的本命宫位，在指定时刻进入哪些流曜。只提供数据，之后交由 Core、限运和专题规则解读。

## 1. 范围与口径

- **唯一体系：既定恒星制，以恒星黄经落宫、落宿。** 不提供赤道模式。
- 仅日、月、金、木、水、火、土、计、罗、炁、孛十一曜；不输出天海冥或星官。
- 地支宫用普通三十度宫：0°起戌，随后酉、申、未、午、巳、辰、卯、寅、丑、子、亥。不使用计算引擎的量天尺宫度。
- 本命人事宫来自已给原盘；星曜按地支叠入本命盘，不计算流年命宫。
- 输入为公历完整时间，必须附时区（北京时间 `+08:00`）。保留秒与微秒，转换 UTC 后计算，不作真太阳时改写。该入口接受 1583–2999 年；回归验证以现代时点为主，不用于历史历法校正。
- 计为真北交点、罗为对点，沿用计算引擎；月孛默认平均远地点，可显式选真远地点。紫炁沿用计算引擎周期模型。
- 速度由恒星黄经中心差分计算，四余不强制标顺。只报即时速度、顺逆；不在本入口判迟留伏、日月蚀、垣殿旺衰、喜忌。计算引擎的伏阈值与现行断法不同，因此不把其状态枚举照搬为既定规则。

## 2. 必须核对宿界

“排盘体系”与“二十八宿边界表”是两项参数；以下选项**均为既定恒星黄经**，不切换赤道体系，也不输出星官。

| 参数 | 用途 |
|---|---|
| `moira_sidereal` | 默认，保留计算脚本 `ZhengCaseSidereal()` 的默认宿界 |
| `xhcl_original` | 计算脚本内置的备选宿界表（原版）；匿名回归样本使用此表，十一曜宫宿度已核验 |
| `xhcl_revised` | 计算脚本内置的备选宿界表（修订版），仅明确使用该表时选取 |

同一星位在不同宿界表下宿内度会不同，临界处还可能换宿。先核原盘／流盘的宿界设置；若用户已给可校验坐标，可据宿名与宿度确认所用表并记录依据。未知时标口径待核，不把默认值冒称原盘口径，不对所有宿度统一加减常数。计算结果不覆盖用户原值。

## 3. 运行

脚本：`scripts/calculate_transits.py`。依赖见同目录 `transit_requirements.txt`，在专用 Python 环境安装；不修改系统环境。

使用已安装上述依赖的 Python 3.10+；虚拟环境创建方法见包根 `开始使用.md`。

从 `qz-reader` 目录调用，先查时点的全量十一曜：

```bash
python -B scripts/calculate_transits.py \
  --at '2026-10-09T01:16:00+08:00' \
  --mansion-profile xhcl_original --format md
```

叠入已核实本命宫位，并重点查看两个宫位：

```bash
python -B scripts/calculate_transits.py \
  --at '2026-10-09T01:16:00+08:00' \
  --mansion-profile xhcl_original \
  --natal natal-palaces.json --focus 官禄 --focus 田宅 --format json
```

`--focus` 可重复，接受地支或人事宫名；宫名必须有本命映射才能定位。JSON 始终保留全量十一曜、十二宫叠入和重点宫列表；Markdown 对重点宫单独列本命星／流曜。

### 不存档调用

`--natal -` 从标准输入读 JSON，输出写到标准输出；也可导入脚本调用 `calculate_snapshot(at, natal=..., focus=[...], mansion_profile=...)`，结果留在内存。不得为运行此工具新建客户 JSON、Markdown 或案例档案。脚本本身没有保存结果、自动归档或覆盖报告的功能。

## 4. 本命映射契约

顶层 `palaces` 必须含十二地支且十二宫名不重复。宫名使用：命宫、财帛、兄弟、田宅、男女、奴仆、夫妻、疾厄、迁移、官禄、福德、相貌。

单宫格式（仅格式示意，不是完整输入）：

```json
{"name": "官禄", "natal_stars": ["日", "炁"]}
```

- `natal_stars` 为十一曜简称数组，`气` 可归一为 `炁`。不能填流曜。
- 未提供本命宫内星时省略该键或填 `null`；原盘明确空宫才能填 `[]`。
- 同颗本命星不能重复分配；若十二宫都给了宫内星数组，十一曜必须完整。
- 不给映射也能查流曜地支与躔宿，但人事宫名为空。禁止由出生年月、当年地支或流曜位置猜本命映射。

## 5. 输出与下游使用

1. `meta`：具体时刻、UTC、儒略日、体系、宿界、月孛口径、节点定义、引擎 SHA-256 与历表版本。
2. `stars`：星曜、完整精度恒星黄经、地支、普通宫内度、本命人事宫、躔宿、曜类、宿内度、速度、是否逆行。
3. `palaces`：地支→本命人事宫、本命宫内星、该时刻流曜，严格分栏。
4. `focus_branches`：调用方指定的已引动／待观察宫位；没有自动吉凶筛选。

Reader 将结果并入数据契约第 9 节，来源标“引擎计算”。Core 沿“原局→宫限→度限→小限／飞限→太岁→年干→顶星→流曜”分析。参与星的全通道、宫宿生克、掌宫、化曜、神煞仍须按已有规则复核；原盘神煞缺失不能由工具补猜，不能拿流曜瞬时速度当旺衰力量。

本流曜脚本只计算时点，不计算整年驻留、入宫区间、顶星、划度、神煞、化曜或起限；年运中的小限、飞限、节气月限由同目录 `annual_period_query.md` 所述 `calculate_periods.py` 自动补算，可按明确采样时刻组合调用。顶星另走 `topstar_query.md`：已有真实行度中心和限年数时，可把同口径、同查询时刻流曜送入既定顶星方法计算。一次立春／生日／十月快照均不能代替全年。多个采样时点也不自动构成精确的入宫／离宫区间。

## 6. 引擎边界与验证

`scripts/vendor/equatorial_stellar.py` 为本入口使用的底层引擎；本入口仅调用既定坐标及宿界查询，不调用量天尺、旧立春年表或旧星官导出。

回归测试：技能包根目录 `tests/test_transit_stars.py`。使用匿名时点星位和虚构本命映射，不包含出生资料或完整客户案例。覆盖十一曜白名单、两个时区同一时点、秒级精度、普通宫界、宿界配置、原始精度、叠宫与无／未知、无文件写入及错误输入。底层引擎日后更新时先重跑测试，再替换副本；不静默改变计算口径。
