# 年运自动补算：小限、飞限与节气月限

## 何时调用

用户给出本命排盘并询问年运／月运时，Reader 从本轮文字核实输入，调用 `scripts/calculate_periods.py`。输出数据并交给 Core 和限运规则，不直接生成吉凶。不要因原盘没有三限而跳过，也不靠模型心算替代程序。

此入口计算三限及节气边界，不计算本命命宫、大限表、顶星、神煞、化曜或旺衰。

顶星按已采用的顶星方法另走 `topstar_query.md`；本程序返回限段不等于已经计算出任意时刻的行度中心，不能用本命命度或线性猜测补齐顶星输入。

## 查询范围与立春年度

年度查询程序返回的是所选年份立春至下一年立春，并非自然年。普通“某年年运”可默认此口径，但输出必须明示公历起止；“全年”没有给起止时也须交代采用口径。用户明确要求公历全年、自然年或自定范围时：

1. 根据真实起止时点确定覆盖哪些立春年度，分别调用现有年度入口。
2. 将各返回区间与用户要求的左闭右开区间取交集，再按时间合并展示，保留所属立春年度及实际交节／交限时刻。
3. 例如公历2027全年需要2026与2027两个立春年度的数据：保留2027-01-01至2027立春、2027立春至2028-01-01两段；丢弃范围外部分，不漏2027年1月，也不带入2028年1月。
4. 展示截点不是交限点，不能把1月1日改称小限换宫。用户所问范围或限表覆盖不完整时，只对缺口标注，保留其余可算数据。

## 公式与时间口径

地支索引为子0、丑1……亥11；结果取模12。

1. **小限**：出生为一岁，每过立春增加一岁。一岁命、二岁财帛，逐年逆行。`小限支 = 命宫支 - (目标立春年度 - 出生立春年度)`。不另设“所有人命宫都从子年起”的第二套起法，不因性别改方向。
2. **月限**：寅为正月，卯二月……丑十二月；出生月和目标月都按节气，非公历月号或农历月号。`月限支 = 当年小限支 - (目标节气月序 - 出生节气月序)`。出生月与所看月相同时在小限本宫。没有额外一宫偏移，也不另从太阴所在宫起算。
3. **飞限**：宫限开始所在立春年度为第1年；交宫当下即切新宫限，下一立春第2年。此为明确采用的程序起算约定，不冒称古文已明确该边界。`n = 目标立春年度 - 交宫立春年度 + 1`，`r = (n-1)%6+1`。第1、2年本宫，第3、4年对宫，第5、6年两个三合宫，第7年回本宫。按既定“子→丑为宫前、顺时针”的坐标：阳支第5/6年分别 +4/+8，阴支分别 -4/-8。飞限不取宫主，不另立太极；只列该宫守星。

小限、飞限年度为立春到下一立春。月界依次为立春、惊蛰、清明、立夏、芒种、小暑、立秋、白露、寒露、立冬、大雪、小寒，下一个立春结束。交节用太阳回归黄经315°起每30°求解；**节气时刻用回归黄经，星曜落宫落宿仍用既定恒星黄经**，二者不混。北京时间固定 UTC+08:00；不改写为真太阳时。

区间左闭右开，交节／交宫／交度时刻归入新段；全年表同时按月界与原盘交宫／度时刻分段。必须写公历起止日期和交节时刻，不只写“六月／七月”。节气根求出后向上取整到秒，作为程序与显示的统一边界（最多不足1秒差异）；输出到秒，不再截成分钟导致边界落回旧月。

## 输入契约

JSON 由 Reader 在内存或标准输入中组装，不要求用户改成 JSON，也不为计算创建客户文件。

```json
{
  "birth_at": "1990-03-20T12:00:00+08:00",
  "birth_month_branch": "卯",
  "palaces": {"十二地支各一项": {"name": "对应人事宫", "natal_stars": null}},
  "palace_limits": [{"start": "2020-06-20T12:00:00+08:00", "branch": "辰"}],
  "degree_limits": [{"start": "2022-03-01T12:00:00+08:00", "mansion": "角木"}],
  "natal_star_details": {}
}
```

以上只示意字段，`palaces` 须按 `transit_star_query.md` 填齐真实十二宫，按命宫→财帛→兄弟等宫序逆行地支；不从出生年月猜宫名。

- `birth_at` 必填，带时区完整公历时间。`birth_month_branch` 可填原盘月柱支，用于核对计算出的出生节气月；不一致即报错，先核出生时间及来源。
- `palaces[*].natal_stars`：已给本命星列表；`[]`明确空宫，省略或`null`未知。十一曜分配沿用流曜工具验证。
- 宫位可附 `shensha`（本命神煞列表）、`annual_shensha`（年份字符串→列表）、`source`；不提供则未知。程序只传递这些输入，不生成神煞。
- `natal_star_details` 可存十一曜逐星原始字段（躔宿、宿度、掌宫、化曜、状态、来源等），按原盘原样保留供后续查阅；不在计算层推断力量与交感。
- 两类限表按 `start` 严格递增，时间须带时区。仅录原盘已有条目，不能估算未给的起限日期；序列最后一项按当前已给表延续，并在元信息中说明未提供下一交限。若资料只覆盖到某日，可传顶层 `limits_valid_until` 明示截止，超出时限运定位留缺。
- 原排盘若首条命宫限只写“某时”而出生有分秒，Reader 须将该条 `start_precision` 明示为 `hour`。仅当它确为首条命宫、同出生年月日小时且整点早于出生时，程序补齐为出生时刻，并保留 `source_start` 与 `normalization`；不带精度来源、非首项或跨小时的提前记录均报错，不静默改动其他交限日期。
- 限表可以缺失；没有覆盖所看时点的宫限时，飞限为未知，不妨碍小限、月限；没有度限表则只留缺度限。不能将未知当空宫。
- 支持公历1584–2998立春年度，出生及查询时刻须在可计算范围内。公历过往出生年、跨年一月、立春前后分别处理。

## 运行与输出

使用已安装 `transit_requirements.txt` 依赖的 Python 3.10+；虚拟环境创建方法见包根 `开始使用.md`。脚本只输出到标准输出，不保存命盘。

```bash
python -B scripts/calculate_periods.py --year 2026 --input - --format md
python -B scripts/calculate_periods.py --at '2026-08-12T12:00:00+08:00' --input - --transits --mansion-profile xhcl_original --format json
python -B scripts/calculate_periods.py --year 2026 --input - --sample '2026-10-09T01:16:00+08:00' --mansion-profile xhcl_original --format md
```

输入 JSON 经标准输入传入。`--at` 和 `--year` 二选一；`--transits`只用于时点，`--sample`可重复，只用于年表。不默认给每个月编造一个代表全月的流盘。宿界／月孛口径见 `transit_star_query.md`，必须保持与已核实原盘一致。

Python API：`calculate_at(at, chart, include_transits=False, ...)`；`calculate_year(year, chart, sample_times=(), ...)`。输出包含：

- 元信息、出生与目标节气月、立春年度和计算约定。
- 当前宫限／度限与起止、小限／月限／飞限地支和本命人事宫，飞限年序和循环位。
- 本命守星、原盘相关神煞、逐星原始资料。小限列宫主，飞限不设宫主字段。
- 全年连续分段表；出生所在年度从实际出生时刻开始，之前不生成限运。
- 显式请求的流曜快照：全量十一曜、各限宫所入流曜及其时刻，与本命守星分栏。

查询只到年或月时，先给三限和原局资料。若要读流曜影响，须选择具体日期时间；一张流盘不能代表全年／整月。流曜精确入离宫区间不在本入口范围内。

## 解读衔接与隐私

仍先原局、宫限、度限，再小限／飞限、太岁、年干、顶星与流曜；月限在年度背景下细分。小限和月限所在人事宫的主题会被激发，宫内星及小限宫主怎样作用、流曜是否生助或克宫，均回原局喜忌与力量判断。特别重视流曜对小限的作用。飞限不新增宫主或三方星为守星。

所有实际参与星曜继续核本宫、对宫、三合及同属性宿度通道，结合落宫、掌宫、化曜、躔宿和神煞取象。“必灾”“必发福”等传统绝对表述只保留为待核断语，不用固定星名代替原局吉凶，不套作确定事件。

测试使用匿名合成条件；不写完整客户案例。用户“不存档”时数据、计算与报告均留在对话／内存，只有通用规则和程序按已有授权同步 Skill 与 Vault。
